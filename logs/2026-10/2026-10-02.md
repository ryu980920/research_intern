# 2026-10-02 — 연구 GitHub 저장소 구축

## 오늘의 목표

연구 과정을 나중에 논문·발표·포트폴리오로 재구성할 수 있도록 재현 가능한 연구 저장소 구조를 만든다.

## 수행 작업

GitHub repository `research_intern`을 생성하고 기본 연구 구조를 구축했다.

초기 구조는 다음 역할을 기준으로 설계했다.

```text
README.md     → 프로젝트 전체 소개
CURRENT.md    → 현재 연구 질문 / 진행 상태 / 다음 작업
docs/         → 연구 방향 / 문헌 / 회의 기록
logs/         → 날짜별 연구 과정
experiments/  → 독립적인 재현 가능 실험
src/          → 재사용 코드
notebooks/    → 탐색 분석
environment/  → 실행환경 재현 정보
```

## 저장 원칙

연구 기록이 다음 연결을 유지하도록 한다.

```text
Research Question
→ Experiment Condition
→ Code
→ Simulation
→ Data
→ Figure / Analysis
→ Interpretation
→ Next Decision
```

특히 `logs/`와 `experiments/`의 역할을 분리한다.

- `logs/`: 그날 실제로 무엇을 했고 무엇을 판단했는지 시간 순서로 기록
- `experiments/`: 하나의 연구 질문을 검증하기 위한 실험을 논리 순서로 기록

## 관찰

저장소를 단순 코드 보관소로 사용하면 연구 판단의 이유가 사라질 수 있다. 따라서 실패한 실행, 설정 변경, 가설 수정도 기록 대상으로 포함한다.

## 이후 수정 가능성

이날 만든 구조는 초기 구조다. 실제 PVT 실험을 진행하면서 불필요한 top-level data 구조나 raw-data 보존 정책은 이후 실험 목적에 맞게 수정할 수 있다.

중요한 것은 과거 결정을 지우는 것이 아니라, **언제 어떤 이유로 바뀌었는지 날짜별 log에 남기는 것**이다.
