## 4. Stage 3A — 기존 GP(A) vs 대체값 제외 GP(B) (완료)

**가설:** 측정 실패로 인한 특수값을 regression GP에서 제외하면, 유효하게 측정된 성능의 예측 오차가 줄어들 것이다.

**실행:**

\`\`\`bash
python experiments/EXP-005_gp_surrogate_reliability/scripts/compare_validity_aware_gp.py
\`\`\`

- **A:** 이전 Stage 2에서 저장한 40-point 학습 GP 예측 그대로 사용 (재학습하지 않음).
- **B:** 같은 ATLAS GP 코드, 각 성능별로 **확실한 대체값에 해당하는 학습 row만 제거**해 재학습.
  - PM: 40 → **39**, D014 제거.
  - UGBW: 40 → **39**, D014 제거.
  - Settling: 40 → **34**, D013/D014/D015/D016/D017/D023 제거.
  - Gain/Ibias/Swing: 변경하지 않음; 이번 A/B에 포함하지 않음.
- **평가:** A/B 모두 D047을 제외한 **같은 검증 설계안 19개**. D047의 무효 PM/UGBW/Settling을 정답으로 채점하지 않음.
- **GP B fitting:** PM 3.22 s, UGBW 1.58 s, Settling 0.82 s, 합계 **5.62 s**. 세 경우 모두 명시적인 MLL fallback 메시지 없음. 신규 SPICE 0회.

| Metric | A MAE | B MAE | A RMSE | B RMSE | 근사 95% 포함률 A→B |
| --- | ---: | ---: | ---: | ---: | ---: |
| PM (°) | 16.8995 | **14.9638** | 21.8781 | **19.0677** | 84.2% → 89.5% |
| UGBW (MHz) | **7.1082** | 9.8395 | **10.5405** | 15.3291 | 89.5% → 89.5% |
| Settling (µs 상당*) | 8005.33 | **7.93263** | 19293.75 | **22.6951** | 100% → 94.7% |

*주의: 나머지 검증 레이블의 settling 유효성도 아직 완전히 증명되지 않았으므로, 시간 단위의 물리적 정확도를 인증한 결과가 아니다. 계산은 동일한 저장 숫자와 단위 변환으로 표현했음.*

**설계점별 분석:** B 오차 개선/악화 개수는 PM **10/9**, UGBW **6/13**, Settling **19/0**. UGBW D052는 실제 약 67.31 MHz, A 약 31.64 MHz, B 약 13.05 MHz로 B가 특히 악화. PM도 모든 설계점에서 일관되게 개선된 것은 아니다.

**Settling GP 추가 관찰:** B의 음수 예측 평균은 **0/19**(A는 **8/19**)이었으나, B가 표준편차 **10 µs를 19개 중 18개에서 동일하게 출력**했다. 실행 중 GPyTorch 경고:
\`\`\`text
NumericalWarning: Negative variance values detected.
Rounding negative variances up to 1e-10.
\`\`\`
\`sqrt(1e-10) s = 10 µs\`와 일치하므로 **posterior 분산의 수치 보정이 작동한 것인지 추가 확인 필요**. MLL fallback=False가 분산 계산의 정상성까지 보장하지 않는다. 이 상태에서는 94.7% 구간 포함률을 모델의 우수한 calibration 증거로 해석하지 않는다.

**판단:** 학습 대체값 제외는 PM/Settling 저장값 오차를 낮췄지만 UGBW는 **더 나빠졌으므로 일괄적 우월성은 입증되지 않았다**. 측정 실패는 failure-design 정보로 별도 보존하고, GP에는 정확한 회귀 레이블만 사용하는 방식의 추가 실험이 필요하다.

## 5. 미실행 / 다음 작업 (Stage 3B는 계획)

**계획:** Settling GP(B)에서 발생한 음수 분산 경고와 정확히 10 µs로 동일한 표준편차(18/19)가 어떻게 발생했는지 확인.

- **GP C(제안):** GP B와 **같은 34개 학습/19개 검증**을 사용하고, \`t_settle\` 값의 표현 단위만 **s → µs**로 변경해 학습. 예측은 공통 단위로 되돌린 뒤 평가.
- **측정값 제거 규칙, kernel, seed를 B와 동일하게 유지**해 단위 표현 영향과 데이터 제거 효과를 분리한다.
- \`Standardize\`로 이상적으로 단위 변화의 영향이 작아야 하므로, 결과가 달라진다면 수치 구현/하한값 등 계산 안정성을 조사한다.
- **Stage 3B의 실행·결과는 아직 없다.** 개선 여부를 선행 확정하지 않는다.

이후에 할 일: waveform 또는 실패 여부 flag를 확보해 **실제 측정 성공/실패를 명시**하고, 실패 정보까지 모델에 반영하는 방법을 검토. EXP-006의 추가 SPICE 평가 여부는 그다음 결정.


## 6. Stage 3B — Settling GP target 단위 변경 및 수치 안정성 실험 (같은 날 후속 실행, 완료)

**왜 했는가?** Stage 3A의 GP B는 19개 검증 설계점 중 18개에서 **정확히 10 µs의 posterior std**를 반복 출력했고 GPyTorch가 `Negative variance values detected`를 경고했다. 이 현상이 매우 작은 단위의 목표값(s)과 관련된 수치 계산 문제인지, 데이터/GP의 구조적 문제인지 구별하려고 했다.

**조건 통제:** 같은 7D 변수, ATLAS 원본 `GPSurrogate`, Matérn 5/2 ARD, seed 42, CUDA 사용. 이전과 동일하게 D013/D014/D015/D016/D017/D023을 제외한 **34개 학습**, D047을 제외한 **19개 검증**. GP B는 초(s), GP C는 같은 값을 1e6배한 마이크로초(µs)로 학습. 예측 평균과 표준편차는 공통 단위로 변환. **신규 SPICE 0회, GP fit 2회.**

**실행:**

```bash
cd ~/research_intern
git pull --ff-only
python experiments/EXP-005_gp_surrogate_reliability/scripts/test_settling_gp_unit_stability.py
```

**실제 WSL 터미널 결과:**

| 항목 | GP B — seconds | GP C — microseconds |
| --- | ---: | ---: |
| Holdout MAE | 7.93263 µs | **7.72849 µs** |
| std 정확히 10 µs인 설계점 | **18/19** | **0/19** |
| GP predict warning | **1건** | **0건** |
| Fit 시간 | 2.56초 | 1.31초 |
| 장치 | cuda | cuda |

B에서 관측된 경고:

```text
NumericalWarning: Negative variance values detected. This is likely due to numerical instabilities. Rounding negative variances up to 1e-10.
```

**재현성 검증:**
- `[REPRO B] Max |new B - Stage 3A B| mean=0 us, std=0 us` — 동일 환경에서 GP B 결과가 **정확히 재현**되었다.
- `[UNITS] Max |C - B| mean=2.25941 us, std=8.951 us` — 모델·데이터가 동일해도 타깃 표현 단위에 따라 예측 평균/불확실성이 달라졌다.
- GP C의 MAE가 약 **2.57% 낮았지만**, 단일 19점 비교이므로 정확도 개선이 일반적으로 보장된다는 의미는 아니다.

**Observation:** s 단위 학습에서 반복된 10 µs std와 음수 분산 경고가 µs 단위 학습에서는 나타나지 않았다.

**Interpretation:** GP posterior 분산의 수치 계산이 타깃 데이터의 절대적인 표현 크기에 **민감함을 관찰**했다. `1e-10` 분산 보정과 10 µs 표준편차는 수치상 일치하지만, **원시 posterior 분산·클리핑 위치·jitter 등 자세한 원인은 아직 분석하지 않았다.** GP C의 불확실성 calibration이 좋아졌다고 결론 낼 수 없다.

**Research implication:** uncertainty를 기반으로 후보를 선택하는 ATLAS에서 수치적인 posterior 변동은 탐색 결과에도 영향을 줄 수 있어, 실제 최적화에 적용하기 전에 검증이 필요하다.

**Next:** 결과 CSV/JSON의 설계점별 B/C 평균·표준편차·MAE/RMSE·interval 포함률을 확인하고, 라이브러리의 수치 보정 경로를 조사한다. 측정 성공 flag도 여전히 필요하며 GP C를 바로 기본 모델로 채택하지 않는다.

## 8. 해석 정정 및 Stage 3B-2 문제 원인 분석 계획

사용자의 문제 제기: **'GP B의 표준편차가 수치 보정값일 가능성이 높은데, 왜 B와 C의 95% 구간 포함률을 정상 모델 간 성능 비교처럼 취급했는가?'**

**정정한 판단:**

- Stage 3B에서 GP B는 검증된 불확실성 모델이 아니라 **문제를 재현하는 대조군**이다. B 94.7% vs C 68.4%의 구간 포함률 차이는 관측값으로 남기지만 **C가 B보다 불확실성 모델로 열등하다는 결론으로 사용하지 않는다**.
- GPyTorch 구현을 재확인한 결과 `MultivariateNormal.variance`가 raw covariance diagonal에 `min_variance`를 적용하는 과정에서, 원래 값이 양수이지만 임곗값보다 작더라도 **'Negative variance values detected' 경고를 출력한다**. 이전에 '실제로 음수가 검출됐음이 확정됐다'고 해석한 표현은 과도했다.
- `torch.float64`의 기본 `min_variance=1e-10`과 원래 단위 초(s)에 대한 `std=sqrt(1e-10)=10 µs`는 일치한다. 그러나 **실제 GP B의 unclipped raw covariance 값은 아직 추출하지 않았으므로 라이브러리 하한의 영향은 현재 가설**이다.

**새 연구 질문:** GP B의 18/19 동일한 10 µs 표준편차는 GPyTorch의 절대단위 분산 하한에서 비롯된 것인가? 보정 전 분산이 **양수/0/음수** 중 무엇인지?

**준비한 실행 코드:** `experiments/EXP-005_gp_surrogate_reliability/scripts/trace_settling_posterior_variance.py`.

- 기존 Stage 3B와 동일한 34개 train/19개 holdout, B와 C 각각 GP fit 1회, seed42. 신규 SPICE 0회.
- 각 설계점의 **raw covariance diagonal / posterior reported variance / min_variance threshold**와 경고 발생 단계, 이전 Stage 3B 예측 재현 여부를 새 CSV/JSON으로 기록.
- **아직 Stage 3B-2는 실행하지 않았다.** 실행 로그를 확인한 후 근본 원인/보정 방법을 결정한다. ATLAS 원본 코드 수정은 하지 않음.
