# 2026-09-29 — ATLAS Environment Smoke Test

## 오늘의 목표

ATLAS 연구를 실제로 진행하기 전에 현재 개발 환경에서 baseline 코드와 SPICE 평가가 정상적으로 실행되는지 확인한다.

이 단계의 목적은 연구 가설을 검증하는 것이 아니라, **앞으로의 실험을 수행할 수 있는 실행 기반이 정상인지 확인하는 것**이다.

## 수행 작업

- 기존 ATLAS 연구 환경에 다시 접속
- `atlas` Python/Conda 환경 사용
- ATLAS 관련 baseline smoke test 실행
- simulation 결과에서 기본 성능 metric이 출력되는지 확인

## 실행 환경 / 조건

확인된 주요 환경:

- Conda environment: `atlas`
- Python 3.10 계열 환경
- ngspice 사용 가능
- ATLAS repository의 실행 코드 사용

실행 중 Torch의 JIT deprecation warning이 발생했지만, simulation 및 metric 출력 자체는 정상적으로 완료되었다.

## Observation

- ATLAS 실행 환경이 정상적으로 동작한다.
- ngspice 기반 회로 평가 결과로 보이는 여러 성능 metric이 정상적으로 반환된다.
- 현재 단계에서는 각 metric이 코드 내부에서 정확히 어디에서 계산되고, 어떤 design parameter와 연결되는지는 아직 분석하지 않았다.

## Interpretation

이번 결과로 확인된 것은 **연구 환경이 실행 가능하다는 것**이다.

반대로 이 결과만으로는 다음을 아직 알 수 없다.

- ATLAS가 어떤 design parameter를 선택했는가?
- 해당 parameter가 어떻게 SPICE simulation으로 전달되는가?
- 출력된 metric이 어디에서 계산되는가?
- PVT / worst-case 평가는 어떤 단계에 포함되는가?
- 이 결과가 optimization 과정에서 다음 candidate 선택에 어떻게 사용되는가?

따라서 다음 단계에서 단순히 더 많은 simulation을 돌리는 것보다 **ATLAS의 실행 흐름을 먼저 추적하는 것이 필요하다.**

## Research Implication

연구 방향을 정하려면 기존 방법에서 실제 병목이 어디인지 알아야 한다.

예를 들어 PVT 평가 비용을 줄이는 방법을 연구하려면 먼저 ATLAS가 현재 PVT 정보를 어떻게 사용하는지 확인해야 한다. 그렇지 않으면 실제 baseline과 관계없는 문제를 개선하려는 실험이 될 수 있다.

## 다음 작업

1. ATLAS Python 코드의 실제 실행 시작점을 확인한다.
2. design parameter가 simulation에 전달되는 흐름을 추적한다.
3. simulation 결과에서 metric이 추출되는 위치를 찾는다.
4. PVT / worst-case 평가가 존재한다면 그 위치와 방식도 확인한다.
5. 이 분석을 바탕으로 첫 정식 Research Question을 정하고, 그 이후 `EXP-001`을 시작한다.
