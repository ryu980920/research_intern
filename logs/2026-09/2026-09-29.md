# 2026-09-29 — ATLAS 실행환경 확인 및 Smoke Test

## 오늘의 목표

ATLAS 연구를 실제로 진행할 수 있는지 확인하기 위해 Linux/WSL 환경에서 ATLAS → ngspice → GF180 연결을 점검하고, two-stage op-amp baseline이 실제로 실행되는지 확인한다.

## 수행 작업

- WSL Ubuntu에서 ATLAS repository 실행환경 확인
- Conda environment `atlas` 활성화
- ngspice 실행 가능 여부 확인
- GF180 primitive model 연결 확인
- `run_experiment.py --help`를 통해 지원 circuit / method / surrogate 옵션 확인
- two-stage op-amp smoke test 실행

## 실행 조건

- Circuit: `two_stage_opamp_gf180`
- Simulator: ngspice
- PDK: GF180 primitive model
- Conda environment: `atlas`

## 결과

Smoke test에서 다음 metric dictionary가 정상 출력됐다.

```text
gain_min      ≈ 69.37
ibias_max     ≈ 6.55e-4
phm_min       ≈ 50.68
t_settle_max  ≈ 1.62e-6
ugbw_min      ≈ 1.78e7
vswing_min    ≈ 0.0181
```

PyTorch의 `torch.jit.script` deprecation FutureWarning이 출력됐지만 simulation 자체는 정상 완료됐다.

## 관찰

- ATLAS Python code가 실제 ngspice simulation과 연결되어 동작함을 확인했다.
- `run_experiment.py`에서 ATLAS, WEIBO, TuRBO, CMAES, Random, MACE, SCBO 등의 method를 선택할 수 있음을 확인했다.
- smoke test 결과는 이후 연구 baseline을 이해하기 위한 출발점으로 사용한다.

## 문제 / 의문

- ATLAS가 내부적으로 어떤 방식으로 design parameter를 netlist에 넣는지 아직 확인하지 못했다.
- PVT mode가 기본 실행에서 실제로 사용되는지 확인이 필요하다.
- optimizer가 다음 candidate를 어떻게 선택하는지 코드 수준의 추적이 필요하다.

## 해석

환경 구축의 목적은 단순히 코드가 실행되는지 확인하는 것이었다. 이 단계에서는 metric 값 자체를 연구 결론으로 사용하지 않는다.
